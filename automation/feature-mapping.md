# Jira Test to automation mapping

This map distinguishes code and local-fixture validation from application execution; it is not evidence that the application passed a Test. Jira Test keys are preserved as tags such as `@AEC-48`. Grouping follows exported Test-to-Story links; no Story is inferred for an unlinked Test.

**Checkout status:** All 22 Checkout Tests have feature scenarios. The rows referring to `checkout-login.feature` or `checkout-orders.feature` are **blocked drafts**, not complete implementations: their step definitions need assertion and fixture validation, and `@pending` prevents execution even when explicitly selected. The local fixture validates checkout controls and one empty-username error path; account login and order submission have not been run against the application. Outside Checkout, 28 Tests still lack feature scenarios.

## Readiness guidance

- All candidates require review of the original Jira description and linked Story acceptance criteria before implementation.
- AEC-101 and AEC-115 have no Story link and no description; do not assign them to a confirmed feature until traceability and test intent are clarified.
- AEC-115 additionally conflicts with the AEC-3 Epic description, which lists promotional coupon application/removal as out of scope.
- AEC-124, AEC-125, and AEC-131 need a controlled mailbox/reset-link mechanism if delivery and link use are to be automated.
- AEC-95 and AEC-96 (account-management Tests) still need reliable browser/session lifecycle handling; AEC-99 also needs its scenario clarified.
- AEC-144 and AEC-145 require an approved non-production order/payment setup. AEC-103 requires a confirmed account/address fixture.
- No Test is declared permanently unsuitable based only on this CSV. Automation suitability must be confirmed after manual-case clarification and environment review.
- Do not store credentials, passwords, customer data, or production secrets in this repository.
